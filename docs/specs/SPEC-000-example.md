# SPEC-000: Example specification

Delete this file once you have written a real one, or keep it as the shape to
copy. `status` is `draft`, `approved` or `superseded`; `tracking` names the
issue that carries this work, or `none` when the spec describes a contract that
is already true and has no open work.

## Problem

What is wrong now, and why it cannot stay that way. Written so that somebody
who was not in the conversation can tell whether it is still true.

## Outcome

What a person can do once this is finished.

## Acceptance criteria

- [ ] A checklist somebody else can verify without asking you what you meant.

## Plan

The steps, in the order they have to happen. This is the part that goes stale
fastest; when it disagrees with the issues, the issues win.

## Out of scope

What this deliberately does not do, so that the next reader does not re-open a
decision that was already made.

## Verification

How the outcome is proven. Name the command.

## References

Decisions and interfaces this depends on: `<repo> ADR <n>`, issues, contracts.
